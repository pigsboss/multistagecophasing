## 1. 监督站位

质量管理**不介入技术判断**（方案好坏、代码实现对错由评审专家与证据说话），只监督两件事：

- 设计开发是否按约定履职：文件齐套、**测试先行**、证据可复现、报告真实、缺陷按归零处理；
- 评审专家是否按约定履职：独立评审（先证据后结论）、意见具体可验证、结论明确、意见闭环、不受进度压力放松要求。

监督方式：**独立取证**（直接查看工作台面、代码、测试输出与原始数据），不采信单方转述。

## 3. 叫停条件（触发即暂停，报用户）

1. 文件未经评审生效即用于启动开发；
2. 测试报告缺失、不可复现，或与工作台面记录矛盾；
3. 评审意见空泛/未闭环仍放行；
4. 未按测试大纲执行即提交"通过"结论；
5. 归零未按"定位准确、机理清楚、问题复现、措施有效、举一反三"执行。

## 4. PDCA 改进机制

- 每阶段执行 **Check**（本检查单）→ 不符合项开具《改进单/不符合项报告》（编号 QM-xxx）→ 明确责任方（设计开发或评审专家）与期限 → **跟踪验证闭环**（Act 也要验证）。
- 改进单模板：问题描述 / 证据 / 依据条款 / 要求动作 / 责任方 / 期限 / 验证方式。
- 改进建议同时面向双方：开发侧（如测试覆盖不足、证据链断裂）与专家侧（如意见空泛、漏审风险项）。
